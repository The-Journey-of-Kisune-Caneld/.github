# Contributing Guidelines

## Standard Contributing Process (Internal)

### 1. Issues
- **Search first:** Before creating a new issue, please check the issue tracker to see if it has already been reported or requested.
- **Use the templates:** When creating an issue, select the appropriate template (Bug Report, Feature Request, Maintenance Request, or Research Request) and fill it out completely.

### 2. Pull Requests
- **Branch naming:** Use descriptive branch names (e.g., `feature/add-auth`, `bugfix/fix-typo`, `chore/update-deps`).
- **Commit messages:** Write clear and meaningful commit messages that explain the "what" and "why" of your changes.
- **PR Template:** When opening a pull request, fill out the provided Pull Request Template. Ensure the checklist is completed.
- **Code Review:** All pull requests require review and approval from at least one other team member before merging.

### 3. Code Style
- Adhere to the established coding standards, linters, and formatters defined within the specific repository you are working on.

### 4. Testing
- Include relevant tests for any new features or bug fixes.
- Ensure that all tests pass locally and in CI before requesting a review.

## Outside Contributing Process
> Thank you for your interest! While we appreciate the community's enthusiasm, we are **not** accepting external contributions or pull requests from outside the core team at this moment. 
> 
> The guidelines below are maintained for internal team reference and for potential future use.
